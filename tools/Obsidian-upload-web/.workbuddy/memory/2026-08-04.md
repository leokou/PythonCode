## 23:30 追加：光标跟随第二次修复（上一版 dispatch scrollIntoView 无效，用户复测仍看不到新增行）

- **实测发现**（Edge headless 测试 `test/cursor-follow-test.html`）：
  1. CM6 内置光标滚动在编辑器**无焦点**事务下完全不生效（scrollTop 保持 0）——预览区同步/工具栏插入/粘贴上传等路径都会踩中；
  2. rAF 阶段浏览器 `scrollHeight` 仍是旧布局值（新增行未计入），手动 clamp 会让滚动距离不足、光标行底部被裁；`view.documentHeight` 未测量时不可靠。
- **最终方案**：`_ensureEditorCursorVisible()` 在 rAF 阶段用 `view.lineBlockAt(head)` 判定光标行是否离开视口，**直接设置 `scrollDOM.scrollTop`（不做手动 clamp，浏览器自动兜底）**，下一帧复测（布局完成、scrollHeight 已更新）仍越界再补滚。验证通过：无焦点事务下内置 scrollTop=0，插件滚动到位且光标行完整可见（cursorLineVisiblePlugin=true）。
- **预览区同侧保障**：新增 `_scrollPreviewCursorIntoView()`（光标块越界才滚，nearest 语义），在 `_doPreviewEnter`（预览区回车，原代码无任何滚动 = 用户"回车看不到新增行"的直接原因）、`_placeCursorAtDocEnd`、图片插入预览区后调用。
- 测试页保留：`test/cursor-follow-test.html`（Edge headless：`--headless=new --virtual-time-budget=5000 --dump-dom`，grep RESULT=）。
- CLAUDE.md 3.1 节已更新为最终实现。

## 23:55 追加：预览区↔编辑区双向同步 bug 修复（用户报告：行尾回车预览区没反应，再按一次才换行）

- **复现方法**：puppeteer-core 驱动系统 Edge headless，`evaluateOnNewDocument` 注入 pywebview stub 后加载真实 `frontend/editor.html`（完整应用环境），`view.dispatch` 打点 + 手动卡 `_skipPreviewRerender` 验证。
- **根因 1（回车后预览区不更新）**：`_syncPreviewToEditor`/`_doFullReplace`/`_doPreviewUndoRedo`/`_insertImageToPreview` 的标志恢复放在 `requestAnimationFrame` 回调里。rAF 执行前的窗口期（dispatch 后 ~16ms 或更长）编辑区 docChanged 被 `if (!_skipPreviewRerender)` 误跳过 → 预览区不渲染，第二次回车才赶上。**验证**：手动置 skip=true 后编辑区回车，doc 已加 \n、预览区不动；恢复标志后第二次回车正常渲染。
- **修复**：① 4 处标志恢复从 rAF 移到 dispatch 后同步位置（rAF 只保留光标恢复/滚动）；② updateListener 兜底：docChanged 且 skip 时若焦点不在预览区则 `_scheduleDeferredPreviewRender()`（setTimeout(0) 后强制渲染，不依赖标志恢复，防异常路径永久卡住）；③ `_syncPreviewToEditor`/`_doFullReplace` 的 `previewEl.focus()` 改为 `_isFocusInPreview()` 条件调用，不再抢编辑区焦点。
- **根因 2（预览区普通输入不同步到编辑器）**：input 事件触发时预览区 DOM 已更新，`block.innerText` 是编辑后文本，`_oldBlockPlainText` 与 `newPlainText` 相同 → diff 恒 null → 同步失败。**修复**：新增 `beforeinput` 监听器（DOM 变更前）捕获编辑前基准 `_oldBlockMarkdown/_oldBlockPlainText/_oldBlockLine`，input 仅调度 debounce 同步。
- **验证**：5 项 PASS（预览区行尾回车回归、编辑区回车回归、标志卡住兜底渲染、预览区输入同步、预览区输入后编辑区回车）。

## 00:15 追加：预览区删除键错位 bug 修复（用户报告：按删键跳过最后一个字删前面的字）

- 用户确认光标滚动"可以了"，新报删除 bug。操作区域：预览区（contenteditable）。
- **根因 1（光标 clamp）**：`_restorePreviewCursor` 里 `Math.min(remaining, len - 1)`——光标应位于文本末尾（remaining===len）时被 clamp 到 len-1（倒数第二个字符后），下次 Backspace 删倒数第二个字。**修复**：改 `Math.min(remaining, len)`。headless 验证：len=4 时修复前 offset 3、修复后 offset 4，与用户描述"跳过最后一个字删前面的字"完全吻合。

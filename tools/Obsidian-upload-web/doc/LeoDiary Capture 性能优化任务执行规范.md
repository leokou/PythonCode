LeoDiary Capture 性能优化任务执行规范
在不改变现有功能、不破坏架构的前提下，对软件进行性能优化。
目标：
降低：
- 内存占用
- CPU占用
- 启动时间
- 页面加载时间
- 文件扫描耗时
- 后台资源消耗
提高：
- 长时间运行稳定性
- 多窗口运行流畅度
- 大文件处理能力
==================================================
一、最高原则
==================================================
禁止：
1. 大规模重构
2. 修改核心架构
3. 删除已有功能
4. 修改已有API接口
5. 将模块重新合并
6. 为性能优化引入复杂依赖
必须：
1. 先分析，再修改
2. 优先解决真实瓶颈
3. 小步提交
4. 每次优化独立验证
5. 保留原功能行为一致
==================================================
二、优化前分析阶段
==================================================
开始优化前：
不要直接修改代码。
先分析：
1. 启动流程
检查：
main.py
包括：
- 窗口初始化
- WebView创建
- API注册
- 托盘初始化
- 热键初始化
输出：
启动耗时分析。
--------------------------------------------------
2. 内存分析
检查：
- WebView实例数量
- CodeMirror加载时机
- Markdown渲染缓存
- 历史记录缓存
- 文件树缓存
- 后台线程数量
输出：
主要内存来源。
--------------------------------------------------
3. CPU分析
检查：
- 定时任务
- watchdog
- 自动保存
- 文件扫描
- UI刷新
- 日志写入
输出：
CPU消耗点。
--------------------------------------------------
4. 文件IO分析
检查：
- pages.json
- history.json
- layout.json
- workspace.json
确认：
是否存在：
频繁读写。
==================================================
三、优化方向
==================================================
按照以下优先级优化。
==================================================
第一优先级：启动优化
==================================================
目标：
减少启动等待。
检查：
禁止启动时：
- 扫描整个workspace
- 加载全部历史
- 初始化所有工具插件
- 加载非必要页面
采用：
懒加载。
例如：
错误：
启动：
扫描：
D:\Obsidian\LeoDiary
正确：
启动：
只读取workspace.json
用户展开目录：
才扫描。
==================================================
第二优先级：WebView优化
==================================================
检查：
当前：
多个窗口是否重复创建WebView资源。
优化：
- 延迟加载页面
- 非活动窗口减少初始化
- 避免重复加载vendor文件
禁止：
删除三个窗口设计。
保持：
Inbox
FlashNote
Daily Log
独立。
==================================================
第三优先级：编辑器优化
==================================================
检查：
CodeMirror 6。
优化：
- 延迟初始化
- 避免重复创建实例
- 大文件限制提示
- Markdown渲染防抖
规则：
输入变化：
禁止：
每个字符立即刷新预览。
采用：
debounce。
==================================================
第四优先级：自动保存优化
==================================================
当前：
2秒debounce
检查：
是否存在：
重复保存。
优化：
保存队列。
规则：
多个Tab同时变化：
合并保存。
禁止：
频繁磁盘IO。
==================================================
第五优先级：资源管理器优化
==================================================
必须使用：
懒加载。
禁止：
启动递归扫描。
要求：
目录展开：
才读取。
增加：
缓存。
例如：
folder_cache
避免：
重复读取相同目录。
==================================================
第六优先级：历史系统优化
==================================================
检查：
history.json。
优化：
- 内存缓存
- 延迟写盘
- 批量flush
保持：
2秒debounce写盘。
==================================================
第七优先级：后台线程优化
==================================================
检查：
所有：
thread
timer
watchdog
确认：
不存在：
无限循环高频运行。
禁止：
while True:
无sleep。
优先：
Event驱动。
==================================================
四、性能监控增加
==================================================
新增：
performance.py
负责：
记录：
启动时间
模块加载时间
文件扫描时间
保存耗时
上传耗时
日志：
performance.log
格式：
[启动]
main_init: xxx ms
webview_create: xxx ms
editor_init: xxx ms
==================================================
五、优化测试标准
==================================================
优化前记录：
1.
启动时间
2.
空闲CPU
3.
内存占用
4.
打开1000文件目录耗时
5.
打开大Markdown耗时
优化后：
必须：
性能提升。
如果没有明显提升：
不要提交。
==================================================
六、代码修改规则
==================================================
新增：
优先新文件。
例如：
performance.py
禁止：
把优化代码全部塞入：
main.py
禁止：
修改：
storage.py
history.py
pages.py
造成接口变化。
==================================================
七、最终目标
==================================================
LeoDiary Capture 达到：
启动快
↓
运行稳定
↓
后台低占用
↓
大目录不卡
↓
长时间运行不泄漏
成为：
类似 Obsidian / VS Code 的长期运行桌面知识工具。
执行顺序：
第一步：
性能分析报告
第二步：
提出优化方案
第三步：
用户确认
第四步：
逐项修改
禁止直接大改。

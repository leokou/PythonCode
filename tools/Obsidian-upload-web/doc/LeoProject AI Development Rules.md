# LeoProject AI Development Rules
版本：V1.0
项目定位：
LeoProject 是 Leo 系列软件统一工程规范。
用于规范：
- Python 桌面应用
- WebView 应用
- AI辅助开发流程
- 项目目录管理
- 长期维护标准
# 1. AI核心开发原则
所有 AI 修改项目必须遵守以下原则：
## 稳定性优先
任何修改不得降低系统稳定性。
禁止：
- 破坏已有功能
- 引入不可控风险
- 修改未知影响范围代码
## 数据安全优先
用户数据保护优先级最高。
禁止：
- 未确认删除数据
- 批量覆盖用户文件
- 修改数据结构导致不可恢复损坏
## 最小修改原则
解决问题只修改必要范围。
禁止：
- 为小问题进行大规模重构
- 修改无关模块
- 顺便优化其他代码
## 模块化设计
保持：
- 高内聚
- 低耦合
- 清晰职责边界
## 向后兼容
修改已有接口必须：
- 保留旧接口
- 提供兼容方案
- 避免影响已有功能
# 2. AI开发执行流程
任何代码修改必须按照以下流程执行。
## 修改前
必须：
1. 阅读 CLAUDE.md
2. 阅读 README.md
3. 理解项目目录结构
4. 定位目标模块
5. 分析调用关系
6. 判断影响范围
7. 输出修改方案
未经分析禁止直接修改代码。
## 修改优先级
按照以下顺序：
第一：
新增独立模块
第二：
扩展已有模块
第三：
修改公共核心代码
核心代码修改必须说明影响范围。
## 修改后
必须验证：
- 功能正常
- 原功能未破坏
- 应用正常启动
- 配置正常加载
- 日志正常
- 构建流程正常
必须输出修改报告：
```
修改文件：
新增文件：
删除文件：
修改内容：
影响模块：
测试结果：
风险说明：
```
# 3. LeoProject目录规范
项目根目录固定：
```
LeoProject/
├── CLAUDE.md  
├── README.md  
├── config/  
├── docs/  
├── lib/  
├── scripts/  
├── bat/  
├── test/  
├── tmp/  
└── data/
```
# 4. 文件归档规则
## config/
用途：
项目配置文件。
存放：
- 环境配置
- 软件配置
- 默认参数
- 功能开关
- 主题配置
禁止：
- 业务代码
- 临时代码
---
## docs/
用途：
项目文档。
包含：
- 架构说明
- 开发规范
- API说明
- 模块说明
- 更新记录
主要文档：
```
ARCHITECTURE.md  
DIRECTORY.md  
MODULES.md  
API.md  
DEVELOPMENT.md  
CHANGELOG.md
```
---
## lib/
用途：
正式运行源码。
结构：
```
lib/
├── core/  
├── backend/  
├── modules/  
└── frontend/
```
所有业务代码必须位于 lib。
---
# core/
用途：
系统基础能力。
负责：
- 应用生命周期
- WebView管理
- 窗口管理
- 配置加载
- 事件系统
- 日志系统
- 插件系统
禁止：
存放具体业务功能。
---
# backend/
用途：
业务服务层。
负责：
- 数据处理
- 文件处理
- Markdown处理
- 网络请求
- 数据同步
禁止：
直接控制UI。
---
# modules/
用途：
独立功能模块。
规则：
一个功能对应一个模块。
结构：
```
module_name/
├── module.py  
├── api.py  
├── config.json  
└── README.md
```
禁止：
- 模块之间直接强依赖
- 跨模块硬编码调用
模块通信优先使用：
- API
- Event
- Service
---
# frontend/
用途：
Web界面。
结构：
```
frontend/
├── components/  
├── themes/  
├── assets/  
└── app.js
```
components：
存放UI组件。
themes：
存放主题样式。
禁止：
UI层直接处理核心业务。
---
## scripts/
用途：
自动化脚本。
负责：
- 构建
- 打包
- 发布
- 清理
- 环境管理
禁止：
存放业务代码。
---
## bat/
用途：
Windows快捷执行入口。
规则：
bat只负责调用scripts。
禁止：
写复杂业务逻辑。
---
## test/
用途：
测试代码。
所有测试必须放这里。
禁止：
测试文件进入lib。
---
## tmp/
用途：
临时文件。
存放：
- 缓存
- 调试文件
- 临时日志
禁止：
保存重要数据。
---
## data/
用途：
用户运行数据。
存放：
- 数据库
- 用户文件
- 附件
- 备份
区别：
tmp：
临时数据
data：
长期数据
# 5. 架构设计规则
## 分层原则
必须保持：
```
UI层  
↓  
业务层  
↓  
数据层
```
禁止：
UI按钮直接执行：
- 数据库操作
- 文件操作
- 核心计算逻辑
必须调用业务层。
# 6. 配置管理规则
所有可变化内容必须配置化。
禁止：
硬编码：
```
路径  
地址  
参数  
功能开关  
用户设置
```
统一使用：
- config.json
- yaml
- 环境变量
禁止：
代码中直接写固定路径。
# 7. 错误处理规则
所有外部操作必须处理异常：
包括：
- 文件操作
- 网络请求
- 系统调用
- 数据解析
- 数据库操作
要求：
- 捕获明确异常
- 写入日志
- 返回明确结果
禁止：
- 空except
- 静默失败
- 吞异常
# 8. 日志规则
正式代码禁止大量使用：
```
print()
```
必须使用统一日志系统。
日志记录：
- 启动
- 关闭
- 错误
- 核心操作
禁止记录：
- 密码
- Token
- 用户隐私数据
# 9. AI禁止行为（红线）
AI不得：
❌ 未阅读规则直接修改代码
❌ 自行改变项目架构
❌ 自行替换技术栈
❌ 删除已有功能
❌ 重写整个项目
❌ 修改无关文件
❌ 添加未确认功能
❌ 引入无必要依赖
❌ 创建重复模块
# 10. 新功能开发规则
新增功能必须：
1. 判断所属模块
2. 创建独立目录
3. 保持接口清晰
4. 更新对应文档
优先：
新增模块
而不是修改核心代码。
# 11. 文件定位规则
窗口：
```
lib/core/window.py
```
配置：
```
config/
```
Markdown：
```
lib/backend/markdown/
```
图片：
```
lib/backend/image/
```
功能：
```
lib/modules/
```
UI：
```
lib/frontend/components/
```
主题：
```
lib/frontend/themes/
```
打包：
```
scripts/
```
测试：
```
test/
```
# 12. 最终目标
所有 LeoProject 项目必须保持：
- 模块清晰
- 边界明确
- 低耦合
- 易测试
- 易扩展
- 易维护
- AI友好
开发方式：
小步修改
最小影响
持续验证
保持可回滚
本文件为 LeoProject AI 强制执行规范。
所有 AI 辅助开发必须严格遵守。
